# 小屋首次进入加载过渡与生产发布

## 目标

- 消除首次开门挂载完整室内资源时出现的突兀白屏。
- 在资源解析、纹理加载和首批 GPU 帧尚未准备好时显示全屏加载过渡。
- 室内准备完成后自然淡出；后续关闭房门不显示加载层，再次打开仅在确有重新准备时显示。
- 完成本地门禁后提交、推送并发布到 `https://love.atimefriend.cn`。

## 视觉与交互方向

- 视觉论点：以深酒红和暖木黑构成全屏幕布，用一线门缝暖光表达“小屋正在点亮”，不使用卡片或通用旋转菊花。
- 内容计划：`LOVE` 品牌、门缝光标、单行状态“正在点亮小屋”、一句极短说明；加载层只负责说明当前状态。
- 交互论点：加载幕布快速显现遮住空白帧，门缝光缓慢呼吸，资源完成并连续渲染数帧后整体柔和淡出；减弱动画模式取消循环动作。

## 技术方案

- 初次场景加载与首次开门室内加载使用同一 DOM 加载幕布，但显示不同文案。
- 在完整室内子树外建立独立 `Suspense` 边界，使室内资源等待不再清空整个花园 Canvas。
- 门户进入 `opening/open` 且当前 epoch 尚未收到室内首帧确认时保持加载层可见。
- 室内资源恢复后等待连续渲染帧，再写入当前 epoch 的 ready 状态，避免资源刚解析就暴露 shader 编译白帧。
- 关闭动作不进入 loading；旧 epoch 的完成信号不得关闭新一次加载。
