# LOVE 后端架构

## 领域边界

- `projects` 保存可变草稿、状态、公开短码和当前发布版本指针；公开短码是 8 位随机 Base62，不承载编辑权限。
- `project_revisions` 保存不可变发布快照。创作者继续修改草稿不会改变已分享内容，只有再次发布才更新公开指针。
- `assets` 只保存服务端生成的对象键和媒体元数据。项目配置只引用 UUID `assetId`，禁止存入 data URL、第三方 URL 或存储凭证。
- `edit_sessions` 保存管理会话哈希。管理链接和恢复码只在签发时返回明文，数据库仅保存使用 `SESSION_SECRET` 生成的 HMAC。
- 场景配置由 `src/domain/loveProjectConfig.ts` 的 Zod schema 统一规范化；发布、预览和根路径都复用同一场景派生器。

## 无账号权限模型

1. 创建项目后，服务端签发一次显示的私密管理链接、恢复码和 30 天 HttpOnly 会话。
2. `/claim/[secret]` 校验管理密钥后立即重定向到工作台，密钥不会继续留在工作台 URL 中。
3. 恢复码可重新建立编辑会话；轮换凭证会同时使旧管理链接、旧恢复码和全部现有会话失效，并为当前请求建立新会话。
4. `/s/[slug]` 与公开 API 只读取当前不可变版本，不返回项目内部 ID、对象键、会话或管理凭证。
5. 撤下分享立即清除发布指针；归档项目会清除发布、会话并标记资产删除，随后尽力删除对象存储文件。

## 媒体处理与隐私

- 单张图片上限 10 MB、最多 2800 万输入像素、每项目最多 9 张；只接受真实可由 Sharp 解码的图片。
- 上传后自动纠正 EXIF 方向、缩放到 1600×1600 内、去除元信息并转换为质量 82 的 WebP。
- 私有草稿媒体必须具有同项目编辑会话；发布版本引用的媒体可由访客读取，但仅缓存 5 分钟，以便撤下后快速失效。
- 删除正在发布版本中使用的照片会被拒绝，创作者需要先撤下分享，避免公开场景出现断图。
- 对象键采用 `projects/<projectId>/photos/<assetId>.webp`；数据库和对象写入失败时执行补偿删除。

## 一致性与安全

- 草稿通过 `draft_version` 乐观并发控制；旧窗口提交返回 409，不能覆盖较新草稿。
- 发布事务锁定项目，校验全部照片属于当前项目且状态为 ready，再写不可变版本并更新发布指针。
- 所有写接口执行同源协议/域名校验和内存速率限制；生产环境拒绝缺失 Origin 的浏览器写请求。
- 全站通过 Next.js Headers 设置 CSP、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff` 等安全边界。
- 数据库迁移按文件名排序，记录 SHA-256 校验值并使用 PostgreSQL advisory lock；已执行迁移禁止原地修改。

## 生产依赖

- Node.js 22 / Next.js standalone。
- PostgreSQL 16。
- S3 兼容存储；当前生产 Compose 使用私网 MinIO，可无损替换为 OSS、R2 或 S3。
- `SESSION_SECRET`、数据库口令和存储口令仅存在服务器秘密文件，不进入 Git、镜像或发布目录。
