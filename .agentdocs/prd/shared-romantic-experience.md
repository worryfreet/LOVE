# 分享页双模式与沉浸浪漫体验方案

## 产品判断

分享页保留“沉浸浪漫”和“自由享受”两种模式，但二者不应在首次打开时被设计成两个同等权重的普通入口。

- **沉浸浪漫**是打开礼物的仪式，也是第一次体验的默认主线。系统控制镜头、行走、开门、花开、光线和流星，只在阅读情书时把时间交还给接收者。
- **自由享受**是礼物被完整打开后的空间。剧情结束后，从同一个机位无缝解锁第一人称控制，让接收者自己逛花园、回看照片和情书。
- 首次访问只突出“开启这份礼物”。为防止晕动、无障碍问题或用户时间不足，保留克制的“跳过剧情，直接漫游”，但不与主按钮争抢视觉权重。
- 完成剧情后，本地记住当前公开版本的完成状态。再次打开同一版本时，入口并列提供“再次沉浸体验”和“自由享受吧”；创作者重新发布新版本后，视为一份更新过的礼物，重新进入首次体验。

这套关系的核心不是“看一段动画，再进入游戏”，而是：**接收者的靠近让花园发生变化，读完信之后才真正拥有这座花园。**

## 首次打开与模式入口

分享链接仍然只有一个，不拆成两个公开链接。

首次打开先呈现极简礼物封面，背景使用已加载场景的柔焦轮廓，不提前暴露完整花园：

> `{recipientName}，有一座花园正在等你。`

- 主按钮：`开启这份礼物`
- 次级文字操作：`跳过剧情，直接漫游`
- 声音默认关闭或等待浏览器授权；点击主按钮这一用户手势同时解锁背景音乐与环境音。

剧情完成后的结束画面不跳转页面，只显示：

> `这座花园的浪漫先到这里，但我想和你的故事，才刚刚开始。`

- 主按钮：`自由享受吧`
- 次级操作：`再看一次`

点击“自由享受吧”后保留当前镜头的位置和朝向，直接解除控制锁，不黑屏、不切场景、不重新加载。

## 沉浸叙事原则

1. **少解释，多发生。** 不连续弹字幕说明“这里很浪漫”，而是让铭牌、花开、照片、信和天空自己表达。
2. **接收者是触发者。** 玫瑰不是按固定时间统一开放，而是随着第一视角靠近，沿路径在视野前方依次盛开。
3. **只保留一次真正的主动交互。** 剧情中只有“打开并珍藏情书”需要接收者亲自完成，因而它会比一路点击“下一步”更有分量。
4. **镜头像人，不像无人机。** 保持第一人称眼高，使用轻微呼吸与步态，但不能摇晃、漂浮或频繁甩头。
5. **情绪先收后放。** 外部远观是期待，铭牌是确认，花开是惊喜，照片和信是亲密，流星与星空文字是情绪顶点，最终把控制权作为礼物交给接收者。

## 约一分钟的剧情时间轴

剧情固定段当前为 **87 秒**，情书阅读阶段完全暂停计时，不计入总时长。增加的时间用于放慢铭牌后的视角回落、主路直行、离屋返回花园和流星开始前的抬头，不压缩照片、情书或星空短句的停留。

| 剧情时钟 | 场景与镜头 | 情绪与交互 |
| --- | --- | --- |
| `00–03s` | 从黑场和轻微风声中淡入，第一视角位于右前方外围野花草坪，完整看到围栏、入口、花海和小屋 | 先给全貌，不立即移动，让接收者知道这是一个真实可进入的空间 |
| `03–09s` | 沿外围草地缓慢靠近入口，镜头始终斜向庭院，前景野花轻轻掠过 | 音乐只出现很弱的主题动机，建立“正在靠近一份礼物”的期待 |
| `09–14s` | 在入口铭牌前自然减速并停留，焦点落到 `TO recipient / FROM sender` | 不叠加解释性弹窗；铭牌本身完成“这是心上人送给我的”这一发现 |
| `14–39s` | 用 3 秒缓慢放下铭牌视角，再只沿主路中线慢速直行并注视屋门；向日葵始终盛开，玫瑰在相机进入花株 XZ 平面 5 米范围时依次开放 | 不左右摇头、不侧看花圃，让开花始终发生在前方视野并保持稳定第一人称观感 |
| `39–44s` | 接近小屋时门自动开启，镜头略微抬起看门廊，再自然进入室内 | 门灯和室内暖光成为新的视觉锚点，外部花海仍可从身后看见 |
| `44–51s` | 沿北墙八联照片墙完成一次连贯横向回望，并在主照片停留约 2 秒 | 不转向已经取消照片的右墙，不逐张弹大图；有照片的墙灯依次变暖 |
| `51–54s` | 镜头走到桌边，落在信封与桌面花艺上，出现唯一一次明确提示：`有一封写给你的信` | 剧情时钟暂停，只开放“打开情书”交互 |
| `暂停` | 接收者亲自打开、阅读情书；只有点击 `珍藏这封信` 才进入下一幕 | 关闭阅读层只回到桌边，不等同于已读；阅读多久都不催促、不倒计时 |
| `54–66s` | 信纸折回信封，镜头重新接管；沿原路缓缓出门，走向花园中段 | 黄昏在这 12 秒内平滑转入夜色，串灯、窗灯与萤火依次亮起；路径中心保留的一朵玫瑰在珍藏后开放 |
| `66–68s` | 到达主路中段后停止平移，镜头单独抬向天空并完成构图 | 流星时间线尚未开始，保证接收者不会在抬头过程中错过流星 |
| `68–78s` | 相机保持仰望，播放 10 秒扩大覆盖范围的流星、全天穹繁星与双倍尺寸星点组字动画 | 流星先出现，随后星点在屋顶上方组成创作者设置的短句 |
| `78–83s` | 星空短句完整停留 5 秒 | 音乐到达情绪顶点后留出短暂空气感，不立即盖上结束界面 |
| `83–87s` | 结束语从画面下部轻轻出现，天空仍然可见 | 展示“自由享受吧”，等待接收者主动接过控制权 |

剧情时间使用场景时钟而不是一串 `setTimeout`。页面切到后台、WebGL 暂停、情书打开或用户主动暂停时，剧情时钟一并冻结，回来后从原位置继续。

## 花朵开放设计

### 开放规则

- 沉浸模式开始时，外围野花、草和向日葵保持自然盛放，所有主花圃玫瑰处于含苞状态。
- 玫瑰按主路前进方向形成连续开放波。让**对应花株在相机进入其 XZ 平面 5 米范围时准确启动**；相机继续前进时完成主要开放过程，接收者能正面看见全过程。
- 单个花区开放时长为 `2.0–2.8s`，同一花区左右两侧错开 `180–350ms`，再叠加少量确定性随机延迟，避免像舞台灯一样整齐切换。
- 已经开放的花在本次会话中永不闭合；跳过剧情或进入自由模式时，所有玫瑰直接处于盛放终态。
- 主路段镜头始终看向屋门，不为花区左右偏转；玫瑰主动进入前方视野并开放，避免系统镜头产生不必要的摇头。

### 技术原则

当前花海玫瑰使用按颜色和 LOD 分组的 `InstancedMesh`，不能为每一株玫瑰创建独立 React 组件或每帧做全量 CPU 距离检测。

- 为每个实例预计算沿剧情路径的开放触发距离，并作为 GPU 实例属性提交。
- 玫瑰花瓣保留含苞与盛放的同拓扑形态，在顶点着色阶段按全局开花波进度与实例触发距离插值；风动继续使用现有共享 uniform。
- LOD 变化只替换几何精度，不重置该株玫瑰的开放进度；低性能设备减少花区数量和局部错峰，不删掉“花为你开放”这一核心体验。
- 开放进度由确定性剧情时钟计算，掉帧后追到正确状态，不让动画因帧率变慢而错过镜头。

## 情书与回忆段

- 照片墙先展示整体，再停留主照片；无论上传 1 张还是 9 张，镜头段都控制在约 7 秒，不逐张巡礼。
- 可以用暖色墙灯强弱变化引导视线，但不使用发光描边、箭头或浮动卡片破坏室内真实感。
- 情书阅读层继续使用现有纸张与信封表现，但需要区分两个事件：
  - `合上/关闭`：回到桌边，剧情仍暂停。
  - `珍藏这封信`：确认阅读完成，恢复沉浸剧情。
- 不通过滚动到底自动判断“看完”，也不设阅读倒计时；“珍藏”这个主动动作就是情绪和流程上的确认。
- 可选的小巧思：珍藏时信纸折回，桌边烛光略亮，室外路径中央最后一朵玫瑰获得开放许可，接收者出门时才会看到它。

## 流星、星空短句与结束语

- 流星段复用现有 10 秒天空动画，但由剧情显式触发，不再依赖分享配置一开始就是 `evening`。
- 从室内走出时，将故事光照从黄昏平滑过渡到夜晚；自由模式接管后保留夜晚状态，避免结尾瞬间跳回白天。
- 当前星点字形只支持 `A–Z`、数字与少量标点。创作者工作台需要限制并实时预览 `skyMessage`，默认继续使用 `I LOVE YOU!`；中文结束语作为屏幕排版呈现，不让不支持的字符在天空中静默丢失。
- 星点短句完整成形后必须保持 5 秒，再显示结束语；流星不循环，避免从珍贵的一次性事件变成常驻屏保。
- 自由模式中提供克制的“再看一次流星”入口，但不自动重复整段剧情。

## 两种模式的明确差异

| 能力 | 沉浸浪漫 | 自由享受 |
| --- | --- | --- |
| 相机 | 系统沿校准路径控制，用户不能与镜头争抢 | 键鼠、触摸第一人称自由控制 |
| 玫瑰 | 初始含苞，沿路线在视野前方开放 | 进入时全部盛放 |
| 房门 | 剧情到达时自动开门 | 靠近后按键或触摸操作 |
| 照片 | 系统完成一次约 7 秒的回忆镜头 | 随时自行靠近观看 |
| 情书 | 唯一的剧情交互，珍藏后才继续 | 随时打开或合上，不改变模式 |
| 天色 | 黄昏到夜晚的剧情曲线 | 首次直接进入时使用创作者配置；剧情后接管则保持结尾夜色 |
| 流星 | 只在结尾播放一次并形成短句 | 不自动播放，可主动重看 |
| UI | 只保留声音、暂停、跳过和必要提示 | 显示漫游提示、声音与“再看流星/再看故事” |

## 创作者工作台需要提供的内容

体验质量主要由系统保证，不让普通创作者调整镜头坐标、移动速度、开花距离或每段秒数。

创作者只配置：

- 是否启用沉浸浪漫，默认开启。
- 现有赠送者、接收者、照片、情书、玫瑰配色与音乐。
- 星空短句 `skyMessage`，限制为当前天空字形支持的字符并提供实时预览。
- 可选中文结束语；未填写时使用系统默认文案。
- 预览操作：`从头预演`、`跳到情书`、`跳到结尾`、`预览自由模式`、`重置花开`。

配置协议应复用现有 `ambience.skyMessage` 与 `ambience.musicAssetId`，只新增真正缺失的体验字段，例如 `immersiveEnabled` 和可选 `endingMessage`，避免维护第二套姓名、照片、信件或天空配置。

## 声音与细节补充

- 点击“开启这份礼物”后才开始声音，满足移动浏览器自动播放限制。
- 声音结构分三段：外围草坪只有风与很弱的音乐；花开时加入一次柔和和声；珍藏后音乐进入完整主题，流星结束时自然收束。
- 脚步、木门、纸张和夜间虫鸣比持续铺满的煽情音乐更能建立真实感；所有声音都必须可一键静音。
- 不建议加入旁白。创作者自己的文字和照片已经足够私人，通用配音反而容易把诚意变成模板感。
- 不默认向赠送者回传“对方已读情书”的个人行为。若以后做数据，只采用明确告知、匿名聚合且可关闭的访问/完成事件。

## 状态机与代码边界

剧情应由一个确定性状态机统一拥有：

```text
cover
  -> reveal
  -> approach
  -> plaque
  -> bloom-walk
  -> interior-entry
  -> gallery
  -> letter-prompt
  -> letter-reading (暂停剧情时钟)
  -> letter-kept
  -> return-garden
  -> finale-sky
  -> ending
  -> free
```

- `mode: 'guest'` 仍然只表达访客权限，另用 `experienceMode: 'immersive' | 'free'` 表达体验控制，避免把权限模式和叙事模式混在一起。
- `garden-experience` 功能层拥有剧情状态机与 UI；场景实体只接收相机、门户、花开、光线、天空等命令，不读取 URL、Cookie 或发布数据。
- 自动镜头与 `FirstPersonController` 不能同时写相机。沉浸期间禁用手动控制，由单一 `RomanticCameraDirector` 沿校准路径更新 position 和 target；切换自由模式时只交接控制权，不重置相机。
- 路径使用现有外围出生点、入口、主路、房门、室内入口、照片墙、情书桌和花园中段锚点，并分别插值位置与注视目标。每个段落使用 ease-in/ease-out，保持相机眼高和地形高度。
- 完成状态按 `slug + publishedRevisionId` 存在本地；只记录完成/跳过与必要断点，不写个人内容。新发布版本自然获得新的体验状态。
- 异常统一降级到自由模式并让所有花盛开，不能因为某个剧情事件失败把接收者锁在不可操作的场景里。

## 无障碍、移动端与异常降级

- 始终提供暂停与跳过。用户切换标签页或失去焦点时自动暂停，不让回来后发现剧情已经演完。
- 遵循 `prefers-reduced-motion`：使用若干固定构图之间的短淡入淡出，取消步态、长距离推镜和大幅抬头，保留铭牌、照片、情书、花开终态与结尾短句。
- 触屏首次进入不依赖 Pointer Lock；剧情结束后再显示左右分区的触控说明。
- WebGL 不可用时不能只显示“设备不支持”。应提供一份静态礼物版本：封面、主照片、赠送关系、情书和结束语仍可阅读，只失去实时漫游。
- 音乐加载失败、照片缺失或设备降级不能阻断剧情；对应段落使用环境音、默认图片或缩短停留继续推进。

## 分阶段落地建议

### 第一阶段：完整叙事闭环

- 分享页礼物封面、首次访问规则、完成状态和双模式入口。
- 确定性剧情状态机、自动镜头路径、第一人称控制交接。
- 自动开门、照片墙段、情书暂停/珍藏恢复、结尾 UI。
- 先以分区花朵显隐或简化含苞形态验证节奏，但验收前必须替换为真实开放动画。

### 第二阶段：核心浪漫效果

- GPU 实例级玫瑰含苞到盛放、路径前方开放波和 LOD 状态保持。
- 黄昏到夜晚的剧情光照、串灯/萤火联动、现有流星与星点短句接管。
- 音乐与环境音分段、移动端画质分级。

### 第三阶段：打磨与正式验收

- 减弱动画、WebGL 静态礼物、后台暂停、刷新断点与异常转自由模式。
- 创作者预演工具、天空字符校验、结束语配置。
- 桌面、移动端和内置浏览器的全流程 E2E、性能与视觉验收。

## 核心验收标准

- 首次访问默认进入沉浸浪漫；完成或明确跳过后才把自由模式提升为主入口。
- 除情书阅读外，剧情固定段稳定为 `87s`；切换后台和打开情书都不会消耗剧情时间。
- 自动镜头不穿墙、不穿家具、不与手动控制争抢，桌面和触屏均可暂停或跳过。
- 向日葵始终盛开；玫瑰从含苞开始，在相机进入花株 XZ 平面 `5m` 范围时启动，并在进入最近观赏距离前完成主要开放过程。
- 花开在 LOD 切换、掉帧、跳段和恢复后保持同一状态，不出现已开的花重新闭合或在身后突然弹开。
- 情书只有点击“珍藏这封信”才恢复剧情；阅读时长不受限制。
- 离屋后天色连续转入夜晚，流星和星空短句只播放一次，短句完整停留至少 5 秒。
- 点击“自由享受吧”后从结尾机位原地解锁，不重新加载、不跳镜头，所有玫瑰保持盛放。
- 新的公开版本会重新触发首次礼物体验；旧版本的本地完成状态不污染新内容。
- WebGL、音频或个别媒体失败时仍能看到赠送关系、照片、情书和结束语，不出现白屏或无法操作的死状态。
