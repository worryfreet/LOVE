# LOVE 前端架构

## 视觉与产品边界

- 花海小院 Canvas 是根路径与分享页的首屏主视觉；导航和操作层必须克制，不使用卡片拼贴遮挡场景。
- 创作者工作台按身份、照片、情书、氛围、发布五步组织；高频内容默认可见，室内空间编辑后置为高级功能。
- 分享页无编辑器、无开发调试、无登录要求，仅保留必要漫游提示、声音开关和无障碍降级。
- 小屋默认照片墙先以目标画面确定主次，再反算米制布局；中央主图必须使用细框和极窄卡纸，避免外框与留白吞掉照片主体面积。

## 运行时边界

- `src/entities/scene/items/cottage-flower-garden` 拥有地形、花海、小屋、门、室内壳体、天空与时间。
- `src/features/garden-experience` 只负责 Canvas、第一人称控制、运行模式和内容装配。
- `src/features/creator-studio` 负责表单、步骤、上传、草稿保存、预览和发布，不重画场景实体。
- `src/server` 负责数据库、对象存储、图片处理、会话、发布和公开读取；客户端不得导入该目录。
- `LoveProjectConfig` 是创作者、API、发布版本与场景之间的唯一内容协议。
- 九个纪念相框必须通过 `photo-01` 至 `photo-09` 显式位置绑定照片；创作者照片步骤直接复刻八联墙面与桌面相框，不得用实例数组顺序或无方位九宫格推断位置。
- 替换照片时先保留旧对象，只有新草稿保存成功后才清理不再被草稿或当前发布快照引用的资源；不可变发布快照引用的旧照片必须继续可访问。
- 小屋门户开门时记录出发侧，访客确实跨过门槛并离开门扇扫掠体后才自动关门；门扇开启期间必须保留到达侧场景内容，避免门洞出现空白。
- 分享页沉浸剧情由 `RomanticStoryRuntime` 的单一秒级时钟负责；自动镜头、门户、玫瑰开放、黄昏转夜和流星天空只读同一帧信号，不各自维护 `setTimeout` 或墙钟。
- 自动导演与 `FirstPersonController` 必须互斥写相机；只有剧情进入 `free` 后才启用第一人称控制，并从终幕当前位置与朝向原地接管。
- 情书阅读的“合上”与“珍藏”是两个事件：合上返回情书门禁，只有珍藏恢复剧情时钟。
- 玫瑰开放波保持既有 InstancedMesh/LOD 分组，通过共享 GPU Uniform 和实例根位置触发；自由模式、跳过或剧情结束后必须稳定保持盛放。

## 验证要求

- 纯函数、schema、短码、会话和发布事务使用 Node.js 内置测试运行器。
- API 与 PostgreSQL/S3 适配器补充集成测试；真实浏览器流程使用 Playwright。
- 视觉改动必须检查桌面和移动视口；分享页必须检查 WebGL 不可用、减弱动画和触摸降级。
